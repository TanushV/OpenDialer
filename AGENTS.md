# Working agreement

Read the active plans `docs/REMEDIATION_PLAN.md` and `docs/EXECUTION_SPEC.md` **in full on every continuation or context compaction**, as the user requires. Read the current checkpoint in `docs/STATUS.md` and cursor/mappings for the active E step in `docs/EXECUTION_TASKS.json`. On initial entry, also read `docs/spec/IMPLEMENTATION_SPEC.md`, `docs/PLAN.md` and `docs/OPTIMIZATION_PLAN.md`; afterward consult their mapped original sections and historical STATUS receipts when needed. This avoids repeatedly mistaking the large historical execution log for current instructions; it does not waive full active-plan reingestion. Do not restart a general audit or choose a different implementation path without a concrete counterexample. The user's standalone local mode extends the original shared-server specification; preserve both modes. The remediation plan owns requirements; the execution specification owns mechanisms, E00–E15 order, tests, removals and delivery. Latest remediation section 1.4 overrides older scopes: proactive freeform Cerebras, advance script batches, five-minute raw retention, all-US DNC, no new recurring commitments, no calendar/CRM sync, rep-booked meetings and final-attempt voicemail. Earlier checked releases are historical evidence, not current completion. Preserve the original specification verbatim; the latest user instruction determines whether the current turn authorizes documentation, audit or implementation.

Write acceptance tests before implementation and retain the red/green evidence in `docs/STATUS.md`. Add regression tests before fixing defects. Update the plan checkboxes as work passes its checks. Commit coherent milestones frequently. Never commit credentials, app databases, recordings, build products, or test caches.

Tests with simulated providers are evidence about software behavior only. Carrier calls, hardware audio, production hosting, account eligibility, legal approval, and outcome lift require their own evidence. Keep those gates explicit; never convert an absent API key into a successful integration claim.

Preserve installed application identity and user data. Use the signed updater for released builds. During local development replace the existing bundle atomically; do not uninstall/reinstall or reset data.
