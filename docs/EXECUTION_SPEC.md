## 1 Fixed decisions and limits

1. One selected authority owns a workspace. Local is one bundled authority process and SQLite; connected is the existing API process, bounded background process, PostgreSQL and Caddy. No local/cloud multi-master synchronization. Voice stays on the desktop–Telnyx–prospect path.
2. Cerebras through OpenRouter is the default for **live interpretation, optional advice and ordinary finalization**. A separately configured stronger reviewer is optional. A Cerebras-only installation must produce a usable rundown; an absent OpenAI key must not disable it. Existing research/LiteLLM/eligible plan adapters remain optional capabilities.
3. One incremental conversation record supplies live help, final rundown, rubric evidence and next-call context. Raw text never becomes the durable source of truth. No separate full-call extraction pipeline.
4. Freeform language remains freeform. Product facts constrain factual claims, not sentence wording. Use structured model judgments and selective independent review, not word overlap, question marks or an objection dictionary as proof of meaning. No software design can guarantee arbitrary natural-language truth; deterministic contract tests and independently reviewed semantic evaluations are separate gates.
5. One attempt-planning implementation supplies future scheduling, capacity and number proposals. Known next attempts and uncertain later retries are different reported quantities. Simple availability and named staffing normalize into identical planner inputs.
6. Statistical learning starts with visible pooled priors and real observations. It does not wait for a manually labeled corpus. No generated history, automatic model promotion, DNC features or invented probabilities for generated sentences.
7. Use existing numbers. Proposals show minimum useful additional capacity, cost and delay, but **new rentals cannot be purchased under the current no-recurring-commitments policy**. Number reuse still has existing carrier costs. Observed health is not a carrier spam-label feed.
8. Every US submission rechecks local DNC and current authorized national screening. Prepaid service access does not establish seller-specific legal authorization. Unsupported/stale coverage stays blocked. Do not infer a B2B exemption.
9. No CRM/calendar integration, booking agent, invitations, meeting synchronization, recording or transcript archive. Reps book meetings elsewhere and report outcomes here. Local callbacks/tasks remain first-class.
10. OpenDialer does not record or archive audio; live microphone frames are used only for the telephony stream. Raw speech, revisions, quoted helper text and model bodies expire within 300 seconds of original receipt. Persist compact paraphrases, human notes, operational metadata and reviewed outcomes. Missing raw evidence after restart is an explicit interpretation gap.
11. Preparation runs before calling: seller templates, gatekeeper/iPhone screening sections, batches and scheduled catch-up. No live research. Voicemail remains final-permitted-attempt only.
12. Deliver 0.3.0 from one frozen source to Mac ARM64 and Windows x64. Preserve `com.opendialer.desktop`, updater key/channel and data paths. Existing machines update in place. macOS 14+ remains the current package minimum; supported Windows versions are established by the native prerequisite checks, not inferred from a successful cross-compile.

Numerical values introduced below are engineering defaults, versioned in one configuration definition. They are not laws, carrier limits, scientifically optimal values or achieved performance. Preserve all current stricter permission, budget and source-lifetime checks.

## 3 Shared contracts and storage decisions

All Python application paths below are relative to `services/backend/app/`; UI paths are relative to `apps/desktop/src/`. A UI component basename denotes the existing `components/` file; `App.tsx`, `context.tsx`, `types.ts` and explicitly qualified state/API files retain their root paths. Migration names are relative to `services/backend/migrations/versions/`. Existing names mean edit in place. A name explicitly marked **new** is a planned file/type, not a claim it already exists.

### 3.1 Mutation and event envelope

Keep existing routes and typed edits. New state-changing contracts require `request_id: UUID`, `expected_version: integer` for the object being edited, and the bounded operation body. Existing effect routes retain their original opaque `idempotency_key`/request identity; do not rewrite historical identities into UUIDs or add a second effect key. Adding expected versions to a route must name the actual object version, not the whole workspace heartbeat. New create operations have no prior object version. Persist a request-content digest before any external effect. Identical replay returns the original receipt; same ID/different content is 409; stale version is 409 with current version and reload guidance. Use 422 for malformed input, 403/404 according to existing scope-hiding behavior, and a named unavailable/pending state for provider uncertainty. Do not use an HTTP timeout as proof an effect failed. Where an old client lacks a newly essential version field, return `client_upgrade_required` for that edit while preserving safe reads and emergency stop; never guess the user's intended version. Test this compatibility boundary before the installed update.

Use the existing scoped event channel. Persist only event type, entity ID/version, sequence and content-free metadata. The client fetches the affected authorized view; raw content comes from the live TTL buffer with remaining lifetime. New relevant event types are `conversation.updated`, `analysis.ready`, `analysis.stale`, `task.changed`, `packet.stale`, `packet.ready`, `screening.changed`, `planning.changed` and `capability.changed`; reuse identical existing names. Reconnect/snapshot overflow never restores raw text from disk.

### 3.2 Conversation record version 2

Reuse the existing `conversation_states` row keyed by call ID. Add **new** `coaching/contracts.py` for Pydantic transport/state definitions shared by live and finalization. Keep `context.py` for pure merge/validation and `workflows.py` for I/O; do not add another service mixin.

```text
ConversationStateV2
  schema_version = 2
  call_id, version, transcript_version, context_fingerprint
  purpose: current call-purpose identity and frozen rubric revision
  observations: bounded Observation[]
  rubric_items: one entry for each frozen rubric dimension
  tracker_matches: current configured tracker IDs and definition versions
  coverage: accepted/interpreted/unavailable segment counts, omitted items
  finalization: pending|ready|partial|unavailable, last_request_id, source_version

Observation
  id: application-generated stable UUID
  kind: need|impact|objection|answer|signal|commitment|rundown|coaching|question|approach
  text: paraphrase, at most 400 characters
  state: open|resolved|confirmed|retracted|stale
  sources: SourceRef[]; replaces: known Observation IDs only
  epistemic_status: model_interpreted|model_reviewed|human_confirmed
  observed_at, available_at, invalidated_at
  review_receipt_id: nullable; no raw provider body

SourceRef
  kind: segment|observation|fact|knowledge|human_note|commitment|outcome
  id, version, occurred_at, available_at
  content_hash: keyed digest; raw_expires_at: nullable
```

These are observation storage categories, not a fixed objection vocabulary. The text remains open-ended. Choose at most 48 observations and 64 KiB serialized durable conversation state, with at most 12 items per category. Retain active promises, unresolved questions and human corrections first, then recent useful context. Authoritative promises/tasks also live in the existing commitment/task rows, so trimming a context packet cannot delete an obligation. Keep omitted counts. Do not grow an append-only narrative through the call.

Each item has at most 32 direct source references. Replacement retains the old observation ID as a source plus its new segment sources rather than copying an unlimited flattened list. Validate against the call's existing records; reject cycles, forward/foreign references and chains deeper than eight. At that bound, compact to a reviewed checkpoint whose source-lineage metadata remains queryable in existing conversation/analysis metadata; never discard the correction relationship silently. Raw expiry changes evidence availability, not the fact that a previously reviewed derived item existed. Correction invalidates dependants; it does not pretend new text was known earlier.

Persist minimal observation revision metadata needed to invalidate an old reviewed checkpoint in `outcomes` records with a scoped key `observation:<call_id>:<observation_id>:<revision>`. Store IDs, source references, review status/hash and replacement relationships there, **not historical paraphrase text**. This avoids maintaining a second narrative archive. The current paraphrase lives once in the conversation state; a human-confirmed task or note retains its own authorized business text.

Migrate version-1 category arrays to the version-2 view idempotently on a copied database, preserving existing IDs/source versions. Mark unreviewed legacy interpretations as such. Never invent a meaning-review receipt during migration. New schemas are emitted only after authority migration; compatibility serializers can expose former arrays to the installed client until the new binary is accepted, then remove the obsolete writer.

### 3.3 Meaning review and inference receipts

Reuse `grounding.review_request`, `ReviewOutput`, `ReviewReceipt` and `accept_review`. A review fingerprints every visible field plus exact source/context versions; it must cover each field once. Review the suggestion, explanation and any displayed alternatives, including implied premises and negation. `NON_FACTUAL` may support ordinary guidance; it cannot confirm a commitment, product fact, outcome or numerical score.

Each actual network attempt owns a distinct usage key and receipt: `live_coach`, `live_coach_review`, `conversation_review`, `conversation_finalize`, or existing preparation roles. Shared call/job identity is not a shared charge identity. Reusing an accepted review is allowed only for an identical fingerprint and still-current source versions. Never persist raw review requests/responses. Apply the existing unsent/submitted/uncertain/settled ledger transitions, including late canceled requests.

### 3.5 Incremental metrics schema

Add two encrypted document tables through **new migration `0017_metric_projections.py`**, after the E02 `0016_completion_context` migration. Reuse the existing document encryption and scoped unique keys:

- `metric_contributions`: one current contribution per source unit and definition version. Operational columns: `source_kind`, `source_id`, `campaign_id`, `definition_version`, `source_version`, `next_refresh_at`; encrypted payload contains the small previous contribution vector and group keys. Unique `(tenant_id,seller_id,external_key)`, key `v<definition>:<namespace>:<source_kind>:<source_id>`. Index due refresh and campaign/source identity.
- `metric_buckets`: UTC-day/campaign/cohort/number/rep summary values and support; encrypted vector, operational `campaign_id`, `bucket_day`, `definition_version`, `bucket_kind`, keyed `group_key`. Scoped unique external key and `(tenant_id,seller_id,campaign_id,definition_version,bucket_kind,bucket_day)` index.

Use the existing `Document` identity/encrypted-data/version columns on both tables. New SQL types are: `source_kind VARCHAR(24) NOT NULL`, `source_id VARCHAR(128) NOT NULL`, `campaign_id VARCHAR(36) NULL`, `definition_version VARCHAR(64) NOT NULL`, `source_version BIGINT NOT NULL`, `next_refresh_at TIMESTAMP WITH TIME ZONE NULL`; bucket-specific `bucket_day DATE NULL`, `bucket_kind VARCHAR(32) NOT NULL`, `group_key VARCHAR(64) NOT NULL`. A null bucket day denotes a whole-cohort total, never a missing daily timestamp. `group_key` is a keyed digest of the canonical grouping values, with values only in the encrypted payload. Contribution indexes are `(tenant_id,seller_id,next_refresh_at)` and `(tenant_id,seller_id,campaign_id,source_kind,source_id,definition_version)`, in addition to the existing scoped unique external-key convention. Definition versions hash the canonical metric/goal/window specification. For a single source row, source version is its current record version. For a compound rep-day union, use the monotonically incremented dirty generation of its scoped coalescing job, and keep the complete input-version fingerprint in encrypted metadata; publication compares both. Retain that generation across completed-job reuse. Do not hash a compound fingerprint into an integer or use a heartbeat timestamp as an idempotency version.

Contribution units are **lead** for unique cohort reach/conversions, **call** for attempt/connected timing/outcomes, **rep-day** for interval union, **usage record** for gross/credit/liability, and **help exposure** for feedback/timing. A lead's second attempt cannot increment unique reach twice. Per-stage count keys include conditioning support and missing-label counts. Corrections subtract the stored previous vector and add the newly computed vector atomically. No raw text or unencrypted phone number is indexed.

E09 storage precision: an active and inactive rebuild must coexist for the same metric definition. Keep the canonical definition hash stable; add the rebuild namespace to the external key above and to the keyed bucket-group identity, with its value in encrypted metadata. This resolves the original unqualified-key collision without a third table or extra operational column. During the bounded rebuild, dirty source jobs update both the active and building namespaces; version/generation fences prevent an older page from replacing a newer contribution. The atomic pointer switch retires the prior derived namespace only after catch-up.

E09 health precision: inbound callback observations reuse the call contribution kind with source ID `callback:<followup_task_id>`. They contribute only callback health counters, never outbound attempts or training rows. Follow-up edits and expiry reverse their previous vector; explicit rebuild pages the existing task table. This adds no table, source-kind enum or service.

The existing job table carries dirty source IDs and replay cursors. Do not add a message broker, event-sourcing framework or general dependency graph. Contribution/bucket tables are disposable derived state, omitted from backup and rebuilt after restore. Do not write aggregate rows synchronously inside a carrier webhook receipt transaction.

E09 bucket lookup precision: define metric-table external keys with ASCII ordering (PostgreSQL `C` collation; SQLite binary ordering), so locale sorting cannot exclude valid hash suffixes from indexed namespace ranges. Use `v<definition>:<namespace>:<keyed-group-digest>` as the bucket external key, retaining the digest-only operational `group_key`. This lets the existing scoped unique index bound active-namespace reads and retired-namespace deletion without decrypting other namespaces or adding another column. Maintain per-rep whole-period totals alongside UTC-day unions. Rolling pickup-window counters move at their original 24-hour/28-day boundaries via the indexed maturation sweep, so report publication does not rescan call history.

E09 indexed-overlap precision: the existing work table is indexed by record creation, which cannot find a corrected interval moved into a different day. In the same unreleased 0017 migration add nullable timezone-aware `work_intervals.op_at` (effective start), `work_intervals.op_due_at` (end or original lease deadline) and `call_attempts.op_work_end_at` (verified rep release/end or bounded live deadline). Add `(tenant_id,seller_id,op_owner_id,op_due_at,op_at)` for intervals and the corresponding call index using `op_work_end_at`. Backfill authenticated metadata in pages of 500 with the existing seller completion marker; preserve source payloads and visible versions. Unsubmitted calls and unknown detached occupancy have no work-end index. This replaces history scans for rep-day corrections, without another table, migration or persistent input-ID list.

E09 dependent-source precision: a suppression references a hashed endpoint, which may belong to many lead records. Add `(tenant_id,seller_id,op_endpoint_id,id)` on the existing lead columns in0017. The originating transaction schedules one content-free `endpoint-leads` expansion; conversion corrections similarly schedule `lead-calls`. Existing ML jobs expand at most100 indexed IDs per page, retaining cursor/generation/lease ownership. They enqueue the normal source contributions rather than recalculating history or writing every dependent lead inside a denial transaction. Neither expansion is another contribution type or new service.

### Chosen generation and review path

1. Move the neutral guidance schema out of `providers/groq.py` into `coaching/contracts.py`. OpenRouter and fixtures import it. Keep a legacy adapter only for explicit migrated configuration; it cannot receive raw speech contrary to the current Cerebras/privacy policy.

3. Pure `ground_guidance` checks schema, scope, source existence/version, current authority, bounds and supplied review fingerprint. 9. Automatic requests use non-streaming compact structured output by default; manual help uses the existing bounded SSE parser. Automatic full deadline stays 1.5 s; manual connect 1 s, first useful ceiling 3 s, full ceiling 8 s, all clipped to source expiry. These ceilings do not replace p95 performance targets.
10. Fix the conflict between the current unconditional 8-second gate and the <2.5-second guidance target. A new final prospect chunk starts a 300-ms trailing debounce; merge subsequent finals during that debounce, then admit the latest current context immediately. Do not wait eight seconds after a completed prospect turn. Revisions/duplicate text alone cannot create another request without changed context; one in-flight request plus one latest pending context per call remains. Rep-only/unknown-side running-state refresh uses the existing 8-second interval and requires new content. Cap automatic admission at 30 requests per call per rolling minute, with explicit rate-limited coverage rather than hidden stale output; manual requests retain their own budget/admission. No semantic phrase whitelist decides which prospect objection deserves interpretation. Quiet `NO_ACTION` still updates context. Manual help has priority; mute affects display only. On sustained overload prioritize oldest not-yet-interpreted content nearing expiry and expose gaps instead of increasing retention. Timing receipts include debounce/coalescing and record rate-limited opportunities; never omit delayed requests from a claimed end-to-end percentile.
