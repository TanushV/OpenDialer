## Hosted relay rollout

The owner approved the in-place rollout on November 11. At 11:28 a.m. Pacific, the Supabase connector applied the
pool, shared application, rep setup and callback migrations on the existing project. The SQL digests match the
tracked files. The deployed source matched the repository for `telnyx-webhook` v4, `managed-setup` v2 and
`callback-fallback` v1. The Mac renewed its lease after the migrations and functions deployed, with four registered
caller IDs and no pending relay events.

Two temporary Supabase Auth users signed in through the deployed setup function and saw only their assigned
workspace and segment. Signed fixture events exercised the existing webhook URL. The receiver rejected a forged
signature, reconciled a sparse event and deduplicated a retry. Both callbacks at the test cap reached their
respective workspaces with the correct prospect reference. The offline fixture selected the hosted path. The
temporary accounts, pool and event records were removed. The four registered Mac caller IDs remained in the relay.

Telnyx has eleven active caller IDs on the standalone Mac application. Four have a signed inbound route registered
in the relay. The dedicated **OpenDialer 2.1 Pilot** Call Control application points to the existing receiver and
has two distinct incoming-only WebRTC credentials on the account's internal SIP connection. The pilot application
has no assigned caller ID. The number ending in 8532 is a candidate because the Mac has no call record or sticky
lead binding for it and the relay has no registration for it.

The hosted worker still needs its Edge secrets and schedule. Carrier audio and the spoken greeting require the
[live pilot](../../REBUILD_PLAN.md#phase-12-shared-calling-in-21) with an approved caller ID, two approved phones,
and two test segments. The signed release follows the live pilot.

## Standalone Mac test after deployment

The owner approved the line ending in 1101. The installed 2.0.0 app had an earlier call to that line awaiting an
outcome. Its saved transcript showed test phrases on both sides. It was finalized through the Dialer as an answered
delivery test so the new session could start.

On the first start, Telnyx delivered the internal audio leg's initiation and hang-up events. The leg timed out
after 30 seconds with SIP 487, before the app submitted an outbound attempt. Restarting the app restored the audio
connection. At 12:00:30 p.m. Pacific the Dialer placed one outbound call in test mode from the number ending in
8693. The destination answered about 11.6 seconds after the attempt was created and Telnyx bridged it about 0.6
seconds later. The Dialer detected voicemail, recorded 8.6 connected seconds and finalized the attempt as
`voicemail`. Calling returned to paused. The test session was ended in Settings and the Mac still showed four
registered caller IDs.

This exercised the installed Mac's standalone route against the updated relay. Human audio and live shared-pool
callbacks still need the two-rep pilot.

## HubSpot numbers already on contacts

The HubSpot connector read the existing test contact and returned the approved line in its Phone property.
The CRM sync uses a valid saved Phone first, then Mobile Phone when Phone is empty or unusable. It normalizes
the selected number before checking or reserving it. A format-only edit keeps the endpoint and its checks.
Changing or clearing the saved number invalidates the old reservation. A replacement needs its own
do-not-call check. Call logs and wrong-number outcomes apply to the number dialed, even if the contact was
edited before wrap-up. Enrichment checks both live phone fields before filling an empty Phone field.

The acceptance suite exercised normal calling from both saved fields with two desktop backends, separate
HubSpot segments, the relay migrations and replayed carrier events. Each callback opened the correct local
prospect at the outbound cap. A rollback-only test through the Supabase connector exercised the hosted
reservation and callback RPCs with two normalized fixture numbers. Each rep's inbox received only its own
callback with the original call reference. The test rolled back its temporary records. The existing relay
still reported four registered caller IDs. The test used no live carrier calls or HubSpot writes.
