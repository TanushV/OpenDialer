# OpenDialer 2.1: shared application verification

Implementation through `d871cfa`. This rehearsal used disposable SQLite stores, a disposable Supabase stack on
this Mac, synthetic signed carrier events and mocked provider requests. It placed no carrier calls.

| Check | Observed result |
|---|---|
| First call from a fresh rep | The Telnyx adapter initially returned `CALLER_NUMBER_ROUTE_REQUIRED` before issuing a request. After the fix, the mocked Telnyx credential check and SIP dial used the rep's assigned audio credential and a pool number. The SIP leg consumed no outbound attempt. Paused and disconnected pools refused audio setup, and the standalone path still worked. Reimported setup took precedence over an old SIP identity. |
| Real local Supabase runtime | Supabase CLI 3.1 applied all six migrations. The deployed setup function issued two private fixture profiles, signed in through real Supabase Auth, and exposed only each workspace's own data and segment. The receiver rejected a forged signature, reconciled a sparse event, deduplicated a signed retry, and kept the second rep working when the default workspace was disabled. |
| Two reps and one caller ID | Two SQLite authorities synced distinct HubSpot fixtures and placed overlapping replay calls from the same number. Both prospect and internal audio legs routed by registered ownership. A cancelled submission preserved the earlier callback owner; a confirmed handoff kept the number and updated the owner. A late earlier receipt did not undo the handoff. |
| Outbound limit | Postgres admitted attempt 90 and refused 91 in shared application mode. A return at the limit still reached the last rep. Reservations and pauses did not spend callback capacity. |
| Offline and recovery | The desktop and worker could not both claim the call. A signed answer recovered an uncertain worker response; retries reused the same Telnyx command ID. A caller who had already hung up produced no carrier action. The worker's answer, greeting and hang-up were verified with signed fixtures and mocked Telnyx HTTP. The intended rep recovered one missed task after repeated delivery. The Cron and Vault setup SQL passed in a rollback-only transaction on the disposable stack. |
| Packaged Mac apps | Both ad hoc signed 2.1.0 apps and their frozen sidecars passed signature and startup checks. Two concurrent app processes authenticated to the local relay. With one app minimized and the other on Settings, two signed fixture callbacks reached only their intended desktops, and both stores attached the prospect. Pilot B switched from Settings to its callback prospect and Decline moved it from Ringing to Ending. Hardware audio was not exercised. |

The connected Supabase project has the two October migrations; the local files now have the same IDs. Four
migrations are pending there: the shared number pool, shared application, rep setup and callback fallback. The CLI
hosted dry run requires a Supabase access token; it stopped before connecting to the database. No hosted schema or
function changed. The account has no staging branch and both free project slots are occupied.
