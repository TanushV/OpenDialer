# Security, retention, and scope

A local launch has a random loopback nonce and OS-protected persistent authority key. Connected sessions are expiring, database-revocable JWTs backed by maintained Argon2 hashing. Every sensitive object is tenant/seller scoped; rep access to call reviews and edits is restricted to their obligations. Master provider configuration is write-only in responses and encrypted in the authority vault. Each rep uses a scoped incoming-only Telnyx credential; server checks reject an outbound PSTN profile before issuing its token. A live account bypass attempt remains a launch gate.

Database business payloads use Fernet authenticated encryption. Desktop cache uses AES-256-GCM with random nonces and namespace-associated data. Database phone lookup keys use HMAC. Directories and newly created secret/journal files have restrictive permissions. Host volume encryption and protected backups remain required because database metadata, process memory and host administration are outside payload encryption. Never delete or rotate a master key without a planned data re-encryption migration and verified backup.

The sample store uses a separate file-protected sample key and contains only fictional data. Never import sensitive or real records into simulation as a substitute for configuring the live workspace.

Recordings and transcription are independently permissioned. Recording links require an authenticated review request and are not included in global snapshots. Optional recordings, transcripts and caches should follow the seller's reviewed minimization/retention schedule and legal holds. The app does not infer employee emotion, honesty or personality and does not authorize consequential employment decisions from scorecards. Required compliance evidence and immutable suppressions must not be purged by ordinary lead imports or model updates.

Inference receives relevant approved context only, never registry datasets or unrelated exports. Public OpenAI requests use store=false. Live help and finalization use Cerebras through OpenRouter only, with ZDR, denied data collection and no provider fallback; a response whose provider cannot be verified as Cerebras is not displayed. Provider-specific retention/account contracts and statutory duties require their own review. No browser cookies or undocumented ChatGPT endpoints are used (the ChatGPT-plan route was removed in 0.3.0). The desktop passes its master key and launch token to the local authority over stdin, never environment variables, and a second authority cannot open the same data directory. Promoted models are served from validated JSON artifacts; serving never unpickles files.

Production exposure is HTTPS behind Caddy. Only signature-verified carrier webhook ingress may be publicly forwarded to a local authority. Operational logs use object IDs and exception classes; tokens, phone numbers, transcript text and recording URLs are not ordinary log fields. Signed updates pin a public key; private signing material remains outside Git and in protected CI secrets. Report suspected leaks by pausing calls, rotating the affected provider/session credentials, preserving audit records and reconciling carrier effects.
